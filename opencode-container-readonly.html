NODO Ø4 · ENTORNOS 04 / 19
Cuatro entornos, un mismo espacio

Ya está todo puesto.

01Python

Python 3 + pip + python3-dev. Venv canónico en <proyecto>/python/: se crea y activa solo. Type checking con pyright, linting con ruff.

02JavaScript

Node.js y npm para scripts, paquetes del ecosistema y soporte de lenguaje vía LSP.

03TypeScript

El mismo toolchain de Node.js más el soporte de TypeScript que opencode activa vía su LSP integrado.

04Rust

Toolchain estable con rustup y objetivo musl para binarios estáticos. Registry, target/ y binarios aislados en <proyecto>/rust/.

Además: git, ssh y gpg; curl, wget y jq para APIs; iptables y Ansible para automatización; y una caja de redes con ping, traceroute, mtr, dig, ss, nmap, tcpdump y tshark.

NODO Ø10 · SEGURIDAD 10 / 19
Add-on opcional de sysadmin
landlock_rosh_

Cuando el servidor es crítico, la sesión remota puede quedar en solo lectura impuesta por el kernel. El agente lee y diagnostica; escribir, borrar o cambiar permisos deja de ser una opción.

  • Se ofrece, no se impone: en hosts críticos o cuando pedís acceso de solo lectura.
  • ro: jaula real de filesystem. log: escritura con auditoría; una traza, no un control.
  • Vive en el servidor remoto: el binario viaja en la imagen y se instala en el target.
  • Si el host ya está restringido, el agente no busca la vuelta: reporta y te deja decidir.
  • Límites claros: bloquea archivos; daemons, señales y red quedan fuera.

La seguridad no depende de que el modelo decida portarse bien: la impone el kernel. Es el compromiso del proyecto con los servidores que administra.

NODO Ø17 · EJECUCIÓN 17 / 19
Cómo se ejecuta

Tres mundos, mutuamente excluyentes.

parámetros
│
├── IMAGEN       --renew · --rebuild · --update
│
├── GESTIÓN      --ps / --ls   ·   --kill / --rm <patrón>
│
└── EJECUCIÓN    <proyecto>
    ├── --no-climb            no busca .git hacia arriba
    ├── --tui | --web         flags > OPENCODE_GUI > web
    ├── --extra-ports <n>,<n> puertos extra host→contenedor
    └── web (default)         servidor web
        ├── --port <1-65535>   default 4096
        ├── -config <ruta>     datos en otra ubicación
        └── --network-host     comparte la red del host
ℹ  --help / -h  y  --version  funcionan en cualquier rama
NODO Ø18 · PUESTA EN MARCHA 18 / 19
Instalación y uso

Listo en unos pocos comandos.

Instalación
git clone <url-del-repo>
cd opencode-container
chmod +x opencode.sh
# acceso cómodo desde cualquier carpeta
ln -s "$(pwd)/opencode.sh" ~/.local/bin/
opencode.sh --rebuild # o --renew para actualizarlo
# desplegar agentes, skills, estilos y comandos
./src/agents_update.sh # o --check
Uso diario
./opencode.sh /ruta/proyecto          # web · 4096
./opencode.sh /ruta/proyecto --tui    # terminal
OPENCODE_GUI=tui ./opencode.sh /ruta/proyecto
./opencode.sh /ruta/proyecto --port 4097
./opencode.sh /ruta/proyecto --extra-ports 3000,8080
./opencode.sh /ruta/proyecto --password "pwd"
./opencode.sh --ps                    # activos
./opencode.sh --rebuild               # imagen

Requisitos: Podman y Linux o macOS. En el contenedor las herramientas ya vienen integradas; en opencode tradicional se suman con ./src/agents_update.sh --install-tools.
